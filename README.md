# Mautic Mail.ru Postmaster

Плагин для Mautic 7.1+, который синхронизирует статистику Mail.ru Postmaster, сохраняет дневные значения в базе, добавляет отчёты и автоматически останавливает кампанию при превышении порога спама.

## Что делает плагин

- Находит уникальные домены отправителей реально созданных писем Mautic; при
  пустом `From` использует эффективного глобального отправителя Mautic.
- Получает через `/ext-api/reg-list/` подтверждённые домены аккаунта Mail.ru Postmaster.
- Сохраняет статистику только для пересечения этих двух списков. Домены, которых нет в письмах Mautic, игнорируются.
- Обновляет дневные снимки из `/ext-api/stat-list-detailed/`; повторная синхронизация текущего дня заменяет значения, а не создаёт дубликаты.
- Показывает сводную страницу Mail.ru Postmaster и дневную детализацию за скользящие последние 30 дней. В сводке письма и жалобы суммируются за это окно, а репутация и доставляемость берутся из последнего дня. Это не общий счётчик отправок Mautic: Mail.ru учитывает только принятый своей инфраструктурой трафик и относит его к DKIM-домену `d=`.
- Добавляет в стандартный конструктор отчётов Mautic источники:
  - `Mail.ru Postmaster — статистика по доменам`;
  - `Mail.ru Postmaster — остановки кампаний`.
- Добавляет действие кампании `Mail.ru Postmaster: блокировка отправки` с отдельными порогами для `spam_percent` и `probably_spam_percent`.
- При превышении порога снимает с публикации всю кампанию, пишет штатный audit log Mautic и отдельную запись о причине остановки. Автоматического повторного включения нет.

## Важное ограничение API

Mail.ru считает статистику по домену DKIM-подписи (`d=`), а не по адресу `From`. Плагин намеренно фильтрует ответ API по доменам `From`, как требуется для отчёта. Поэтому DKIM-домен письма должен совпадать с доменом `From`; иначе Mail.ru не вернёт для него сопоставимую строку.

Для письма без явного корректного адреса `From` плагин использует эффективный глобальный адрес отправителя Mautic. Динамические токены в `From` не подставляются при построении списка.

## Требования

- Mautic `7.1` или новее;
- PHP `8.2` или новее;
- расширение PHP `intl` рекомендуется для IDN-доменов;
- доступ к Mail.ru Postmaster API и подтверждённые домены.

## Установка

### Composer из приватного GitHub-репозитория

Добавьте приватный VCS-репозиторий в корневой `composer.json` Mautic и установите пакет:

```bash
composer config repositories.mautic-mailru-postmaster vcs https://github.com/AlexanderZlobinM1/mautic-mailru-postmaster-plugin.git
composer require alexanderzlobin/mautic-mailru-postmaster-bundle:dev-main
php bin/console mautic:plugins:reload
php bin/console cache:clear
```

### Вручную

Скопируйте содержимое репозитория в:

```text
docroot/plugins/MauticMailRuPostmasterBundle
```

Для классической структуры Mautic путь может быть `plugins/MauticMailRuPostmasterBundle`. Затем выполните:

```bash
php bin/console mautic:plugins:reload
php bin/console cache:clear
```

## Настройка токена

1. Откройте **Настройки → Плагины → Mail.ru Postmaster**.
2. Перейдите по ссылке получения токенов в подсказке.
3. Авторизуйтесь аккаунтом-владельцем доменов.
4. Скопируйте всю JSON-строку, например:

   ```json
   {"access_token":"…","expires_in":3600,"refresh_token":"…"}
   ```

5. Вставьте строку в единственное поле API-ключа и включите интеграцию.

На плитке используются стандартная форма интеграции Mautic, отдельный
выключатель, поле JSON-токена, короткая инструкция со ссылкой и copyright
Sales-snap.ru. Это единственное место
глобальных настроек плагина; отдельного раздела в общей конфигурации Mautic нет.
Пороги остановки не являются глобальными и задаются в блокировщике конкретной
кампании.

Значение хранится в зашифрованных настройках интеграции Mautic. Плагин обновляет часовой `access_token` через `refresh_token` и сохраняет обновлённый JSON обратно. Токены не записываются в логи.

## Синхронизация через MCD или cron

Если на хосте установлен MCD и выбран любой активный профиль (не `passive`),
он автоматически обнаруживает плагин именно на этом экземпляре Mautic и по
настраиваемому интервалу запускает единственную штатную команду. Она каждый раз
перечитывает скользящие последние 30 дней:

```bash
php bin/console mautic:mailru-postmaster:sync --current-month --no-interaction
```

В MCC у такого экземпляра появляется плитка **Mail.ru Postmaster Sync** с
выключателем и интервалом. На экземплярах без плагина плитка скрыта, а команда
не запускается. MCD остаётся только планировщиком: логика API находится в
плагине, изменения кода агента для этой интеграции не нужны.

Быстрый стоппер не планируется через MCD. Его watcher автоматически запускает
обычный `mautic:campaigns:trigger`; совместимая команда `--active-guards`
сохранена только для ручной диагностики.

Если MCD не установлен или работает в режиме `passive`, добавьте cron только
для обновления доступного 30-дневного окна отчётов:

```cron
*/10 * * * * cd /path/to/mautic && php bin/console mautic:mailru-postmaster:sync --current-month --no-interaction >> /dev/null 2>&1
```

Можно задать точный период только внутри доступных последних 30 дней:

```bash
php bin/console mautic:mailru-postmaster:sync --date-from=2026-08-01 --date-to=2026-08-09
```

Документация Mail.ru разрешает запрашивать период до 365 дней, но на живом
аккаунте оба метода статистики фактически возвращают только скользящее окно
последних 30 дней: точные старые диапазоны завершаются с `ok: true`, но пустыми,
а годовой запрос возвращает те же последние 30 дат. Поэтому плагин сознательно
не делает глубоких чтений, не сохраняет их пустые/обрезанные результаты и не
пытается воспроизвести историю веб-интерфейса. Устаревшие флаги `--full`,
`--full` и `--force-rescan` оставлены только для совместимости и безопасно читают
те же последние 30 дней. Устаревший минутный вызов `--scheduled-full` завершается
без обращения к API; фактическое обновление выполняет только `--current-month`.

Список доменов строится по всем сохраненным письмам текущего экземпляра Mautic. Явный `From` имеет приоритет; для писем с пустым `From` берется общий адрес отправителя Mautic. Домены соседних инсталляций на том же хосте не читаются.

После успешной штатной синхронизации строки старше 30 дней удаляются. Отчёты
также всегда ограничивают выборку этим окном, поэтому ранее накопленные глубокие
значения не участвуют даже до очистки.

## Блокировка кампании

1. В конструкторе кампании нажмите `+` → **Действие** и выберите **Mail.ru Postmaster: блокировка отправки**. Узел разрешено ставить непосредственно перед действием отправки письма.
2. Выберите домен отправителя. В списке присутствуют только домены, реально найденные в письмах этого Mautic; пустой `From` учитывается как общий отправитель Mautic.
3. Укажите два порога в процентах:
   - `Возможно спам` (`probably_spam_percent`);
   - `Точно спам` (`spam_percent`).
4. Опубликуйте кампанию.

Быстрая защита не зависит от MCD или отдельного cron. Обычная команда Mautic
`mautic:campaigns:trigger` запускает фоновый процесс плагина для кампании с
guard-узлом. Сам trigger и отправка писем никогда не ждут Mail.ru API и не
перехватываются перед каждым сообщением. Фоновый watcher опрашивает только
текущий день нужного домена с разрешённым интервалом и снимает кампанию с
публикации, как только ответ превышает заданный порог.

Параллельные trigger-процессы используют один неблокирующий lock на домен.
Если другой watcher уже выполняет медленный API-запрос, новый процесс сразу
продолжает работу без повторного запроса; следующая попытка разрешается через
7 секунд. Поэтому письма, отправленные до появления статистики или во время
интервала, не задерживаются, а последующие прекращаются после остановки
кампании.

Кампания останавливается, только если значение **строго больше** порога,
статистика относится к текущему дню и была синхронизирована не более 20 минут
назад. Если API недоступен или свежих данных нет, плагин не останавливает
кампанию на основании устаревших цифр. Фоновая команда синхронизации остаётся
для отчётов и использует тот же межпроцессный ограничитель, но для работы
быстрого стоппера не требуется.

Каждая проверка записывается в отдельный ротируемый журнал плагина с маркером
`mailru_postmaster.guard_evaluation`. Запись содержит источник проверки,
решение, время проверки, ID кампании/узла/письма, домен, время синхронизации и
возраст снимка, значения Mail.ru и настроенные пороги. На стандартной установке
посмотреть записи за текущий день можно так:

```bash
grep 'mailru_postmaster.guard_evaluation' var/logs/mailru_postmaster_guard-$(date +%F).log
```

## Хранение данных

С учётом префикса таблиц Mautic создаются:

- `mailru_postmaster_stats` — одна актуализируемая строка на домен и день;
- `mailru_postmaster_guard_stops` — неизменяемый журнал автоматических остановок.

Удаление или выключение плагина не включает остановленные кампании автоматически.

## Разработка и проверка

```bash
composer install
composer test
composer lint
```

Интеграция разработана и проверяется на Mautic 7.1.3 / PHP 8.4.
