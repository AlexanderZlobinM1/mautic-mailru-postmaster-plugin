# Mautic Mail.ru Postmaster

Плагин для Mautic 7.1+, который синхронизирует статистику Mail.ru Postmaster, сохраняет дневные значения в базе, добавляет отчёты и автоматически останавливает кампанию при превышении порога спама.

## Что делает плагин

- Находит уникальные домены в явном поле `From` реально созданных писем Mautic.
- Получает через `/ext-api/reg-list/` подтверждённые домены аккаунта Mail.ru Postmaster.
- Сохраняет статистику только для пересечения этих двух списков. Домены, которых нет в письмах Mautic, игнорируются.
- Обновляет дневные снимки из `/ext-api/stat-list-detailed/`; повторная синхронизация текущего дня заменяет значения, а не создаёт дубликаты.
- Показывает сводную страницу Mail.ru Postmaster и детализацию по годам/месяцам. В сводке письма и жалобы суммируются по всей сохранённой истории, а репутация и доставляемость берутся из последнего дня.
- Добавляет в стандартный конструктор отчётов Mautic источники:
  - `Mail.ru Postmaster — статистика по доменам`;
  - `Mail.ru Postmaster — остановки кампаний`.
- Добавляет действие кампании `Mail.ru Postmaster: блокировка отправки` с отдельными порогами для `spam_percent` и `probably_spam_percent`.
- При превышении порога снимает с публикации всю кампанию, пишет штатный audit log Mautic и отдельную запись о причине остановки. Автоматического повторного включения нет.

## Важное ограничение API

Mail.ru считает статистику по домену DKIM-подписи (`d=`), а не по адресу `From`. Плагин намеренно фильтрует ответ API по доменам `From`, как требуется для отчёта. Поэтому DKIM-домен письма должен совпадать с доменом `From`; иначе Mail.ru не вернёт для него сопоставимую строку.

Для письма без явного корректного адреса `From` плагин использует эффективный глобальный адрес отправителя Mautic. Динамические токены в `From` не подставляются при построении списка.

## Требования

- Mautic `7.1` или новее;
- PHP `8.2` или новее;
- расширение PHP `intl` рекомендуется для IDN-доменов;
- доступ к Mail.ru Postmaster API и подтверждённые домены.

## Установка

### Composer из приватного GitHub-репозитория

Добавьте приватный VCS-репозиторий в корневой `composer.json` Mautic и установите пакет:

```bash
composer config repositories.mautic-mailru-postmaster vcs https://github.com/AlexanderZlobinM1/mautic-mailru-postmaster-plugin.git
composer require alexanderzlobin/mautic-mailru-postmaster-bundle:dev-main
php bin/console mautic:plugins:reload
php bin/console cache:clear
```

### Вручную

Скопируйте содержимое репозитория в:

```text
docroot/plugins/MauticMailRuPostmasterBundle
```

Для классической структуры Mautic путь может быть `plugins/MauticMailRuPostmasterBundle`. Затем выполните:

```bash
php bin/console mautic:plugins:reload
php bin/console cache:clear
```

## Настройка токена

1. Откройте **Настройки → Плагины → Mail.ru Postmaster**.
2. Перейдите по ссылке получения токенов в подсказке.
3. Авторизуйтесь аккаунтом-владельцем доменов.
4. Скопируйте всю JSON-строку, например:

   ```json
   {"access_token":"…","expires_in":3600,"refresh_token":"…"}
   ```

5. Вставьте строку в единственное поле API-ключа и включите интеграцию.

На плитке используются стандартная форма интеграции Mautic, отдельный выключатель, поле JSON-токена, короткая инструкция со ссылкой и copyright Sales-snap.ru.

Те же настройки доступны отдельным пунктом **Настройки → Конфигурация → Mail.ru Postmaster**: включение, JSON-токен, retention и недельное полное обновление. Обе формы работают с одной зашифрованной записью интеграции; токен не копируется в `config/local.php`. Пороги остановки не являются глобальными и по-прежнему задаются в блокировщике конкретной кампании.

Значение хранится в зашифрованных настройках интеграции Mautic. Плагин обновляет часовой `access_token` через `refresh_token` и сохраняет обновлённый JSON обратно. Токены не записываются в логи.

## Синхронизация через MCD или cron

Первичное или принудительное полное заполнение за максимально доступные 365 дней:

```bash
php bin/console mautic:mailru-postmaster:sync --full
```

Если на хосте установлен MCD и выбран любой активный профиль (не `passive`), MCD автоматически обнаруживает плагин именно на этом экземпляре Mautic и каждые 10 минут обновляет только текущий календарный месяц:

```bash
php bin/console mautic:mailru-postmaster:sync --current-month --no-interaction
```

В MCC у такого экземпляра появляется плитка **Mail.ru Postmaster Sync** с выключателем и интервалом. На экземплярах без плагина плитка скрыта, а команда не запускается.

Если опубликованная кампания содержит действие **Mail.ru Postmaster: блокировка отправки**, MCD дополнительно проверяет наличие активного guard-узла и запускает доменную команду:

```bash
php bin/console mautic:mailru-postmaster:sync --active-guards --no-interaction
```

Она запрашивает только домены писем из активных guard-узлов, уже подтвержденные обычной синхронизацией. Если у письма пустой `From`, используется эффективный общий `mautic.mailer_from_email` из контейнера Mautic (включая значение из переменной окружения). Без активных кампаний API не вызывается. Интервал — 7 секунд: официальный лимит равен 10 запросам в минуту на домен, а одна дополнительная секунда оставляет запас для штатного запроса и повторов.

Раз в неделю MCD выполняет резервный полный sync за 365 дней. По умолчанию это воскресенье, 03:00 по локальному времени экземпляра. День и время задаются в настройках плагина; сохранённое в MCC расписание имеет приоритет.

Если MCD не установлен или работает в режиме `passive`, добавьте cron вручную. Первая строка обновляет только текущий месяц, вторая раз в неделю перечитывает доступный год, третья обеспечивает частую проверку активных блокировщиков без наложения двух процессов:

```cron
*/10 * * * * cd /path/to/mautic && php bin/console mautic:mailru-postmaster:sync --current-month --no-interaction >> /dev/null 2>&1
0 3 * * 0 cd /path/to/mautic && php bin/console mautic:mailru-postmaster:sync --full --no-interaction >> /dev/null 2>&1
* * * * * flock -n /tmp/mautic-mailru-postmaster-active.lock sh -c 'cd /path/to/mautic || exit 1; for i in 1 2 3 4 5 6 7 8; do php bin/console mautic:mailru-postmaster:sync --active-guards --no-interaction; sleep 7; done' >> /dev/null 2>&1
```

Можно задать точный период:

```bash
php bin/console mautic:mailru-postmaster:sync --date-from=2026-08-01 --date-to=2026-08-09
```

API Mail.ru ограничивает период 365 днями и фактически отдает не более 30 дневных строк на домен за один детальный запрос. Плагин автоматически делит длинный backfill на 30-дневные окна и выдерживает 7 секунд между ними. Обычная синхронизация перечитывает только текущий месяц; уже сохранённые старые месяцы не затрагиваются до еженедельного полного sync или явного `--full`.

Список доменов строится по всем сохраненным письмам текущего экземпляра Mautic. Явный `From` имеет приоритет; для писем с пустым `From` берется общий адрес отправителя Mautic. Домены соседних инсталляций на том же хосте не читаются.

В настройках интеграции поле **Хранить статистику** задает 30, 90, 180 или 365 дней. По умолчанию хранится максимально доступная история — 365 дней. Удаление более старых строк выполняется только после успешной штатной синхронизации.

## Блокировка кампании

1. В конструкторе кампании нажмите `+` → **Действие** и выберите **Mail.ru Postmaster: блокировка отправки**. Узел разрешено ставить непосредственно перед действием отправки письма.
2. Выберите то же письмо, которое отправляет следующий узел. Домен берётся из явного `From` этого письма.
3. Укажите два порога в процентах:
   - `Возможно спам` (`probably_spam_percent`);
   - `Точно спам` (`spam_percent`).
4. Опубликуйте кампанию.

Проверка происходит после каждого cron-sync и дополнительно в момент выполнения блокирующего узла. Кампания останавливается, только если значение **строго больше** порога, статистика относится к текущему дню и была синхронизирована не более 20 минут назад. Если API недоступен или свежих данных нет, плагин не останавливает кампанию на основании устаревших цифр.

## Хранение данных

С учётом префикса таблиц Mautic создаются:

- `mailru_postmaster_stats` — одна актуализируемая строка на домен и день;
- `mailru_postmaster_guard_stops` — неизменяемый журнал автоматических остановок.

Удаление или выключение плагина не включает остановленные кампании автоматически.
